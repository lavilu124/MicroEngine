# MicroEngine — project guide

A Windows-only 2D C++ game engine built on **SFML 2.6.1**, with an ImGui/Walnut-based
editor GUI. One Visual Studio solution, three projects, generated by **premake5 (Lua)**.

## Projects
- **MicroEngine** (`MicroEngine/`) — the engine core. Builds as a **DLL** (`Micro`).
- **SceneEditor** (`SceneEditor/`) — the editor GUI (ImGui + Walnut from The Cherno). Links `Micro` + `Walnut`.
- **SendBox** (`SendBox/`) — personal test/sandbox app. Links `Micro`.

## Build & run (Windows)
Prereqs: Visual Studio 2022, **Vulkan SDK** (needs `VULKAN_SDK` env var — used by Walnut/SceneEditor).

```sh
# 1. Generate the VS solution (or run Scripts/Setup-Windows.bat)
./Vendor/Binaries/Premake/Windows/premake5.exe --file=Build.lua vs2022

# 2. Build (or just open "Micro Engine.sln" in VS and hit F5)
"C:/Program Files/Microsoft Visual Studio/2022/Community/MSBuild/Current/Bin/MSBuild.exe" \
  "Micro Engine.sln" -p:Configuration=Debug -p:Platform=x64 -m
```
- Configs: **Debug / Release / Dist** (Dist = SceneEditor as WindowedApp). Platform: x64 only.
- Output: `Binaries/windows-x86_64/<Config>/<Project>/` (e.g. `.../SceneEditor/SceneEditor.exe`, `Micro.dll`).
- Premake is at `Vendor/Binaries/Premake/` (do **not** re-add the old `vendor/bin/premake` — it was removed as a duplicate).

## Build-system conventions (premake Lua)
- Per-project scripts: `Build.lua` (workspace) → `Build-Walnut-External.lua`, `MicroEngine/Build-Core.lua`,
  `SceneEditor/Build-Walnut-App.lua`, `SendBox/Build-App.lua`, `Walnut/*.lua`.
- Vendored deps live under lowercase **`vendor/`** — canonical casing: `vendor/imgui`, `vendor/GLFW` (capital
  GLFW), `vendor/glm`, `vendor/spdlog`, `vendor/yaml-cpp`, `vendor/stb_image`. Keep casing exact.
- `.sln`/`.vcxproj`/`Makefile` are **generated** (git-ignored) — never hand-edit; change the `.lua` and regenerate.
- Known gap: `xcopy`/`del` build steps and `$(SolutionDir)`/`$(OutDir)` command macros are Windows-only;
  true Linux `gmake` support is not wired up. The `SceneEditor/templates/setupProject/` scaffold still has
  the old `Vendor` casing bugs + its own premake copy (fix if/when project-creation is touched).

## MicroEngine core — feature map
Public API is the umbrella header `MicroEngine/src/Micro.h`. `MICRO_API` (Core.h) = dllexport/import.
- **Entry point** (`EnteryPoint.h`): engine owns `main()`, reads `argv[1]` as scene name, calls user's
  `Micro::CreateApplication(scene)`. Games subclass `Application` (window, maxFPS, virtual Run/Display/InputFunc,
  `m_inGUiMode` = hosted-by-editor flag).
- **SystemManager** — central hub: object CRUD, collision queries, input, scene load, camera, lighting, UI,
  static `deltaTime`.
- **Objects**: `GameObject` (transform, layer, level/z-order, visibility, virtual Start/Update/OnCollision/OnTrigger);
  `ObjectManager` factory-registry with `REGISTER_GAMEOBJECT(Type)` (custom classes spawnable by name);
  `Animation` (sprite-sheet); `Camera` (follow-by-name, zoom, sf::View).
- **UI**: `Text`, `Button` (normal + on-click sprite, function-pointer callback).
- **Input** (`Micro::Input`): `InputAction` — data-driven `std::variant` over keyboard/mouse/controller-buttons/
  mouse-move/joystick-axes; Started/Pressed/Released; controller dead-zone + axis groups.
- **Collision** (`Micro::Collision`): layers (COLLIDER, 10 custom, TRIGGER, IGNORE, ALL); bounding-box, circle,
  and pixel-perfect (alpha bitmask).
- **Files** (`FileManager`): resource-dir scanning + caches for sprites/sounds/fonts; scene object loading;
  input config (name→function-pointer maps); logging (`MC_LOG`, debug-only).
- **Lighting** (`ls::`, derived from the *Candle* SFML lib): raycasting 2D light/shadow. `LightSource`
  (RGB color + alpha intensity, range, fade, additive), `RadialLight` (beam angle), `DirectedLight` (beam width),
  `LightingArea` (FOG / AMBIENT fog-of-war, backs `SetDarkness`), geometry (Line/Polygon) + edge pool for shadows.

Data-driven throughout: scenes, assets, input maps, and custom entity classes are all resolved by name from
files — which is what makes the SceneEditor possible.
